# RustFS et S3

## Qu'est-ce que S3 ?

Amazon S3 est une interface de stockage objet : les données sont stockées sous
forme d'objets identifiés par un bucket et une clé, par exemple
`s3://iceberg-warehouse/analytics/data/...`. S3 n'est pas un système de
fichiers POSIX : les préfixes servent à organiser les clés, mais ne sont pas
des répertoires classiques.

Le stockage objet est adapté aux data lakes car il est durable, accessible par
HTTP et découplé des moteurs de calcul. Iceberg écrit lui-même ses fichiers
Parquet et ses métadonnées dans S3 ; plus aucun composant du projet ne dépose
de fichiers "à la main".

## RustFS dans ce projet

RustFS est l'implémentation locale compatible avec l'API S3. Le service Docker
stocke ses données dans le volume `rustfs-data` et expose :

- API S3 : `http://localhost:9000`
- Console : `http://localhost:9001`

Le sink (`sink.py`) utilise `boto3` pour vérifier/créer le bucket du
warehouse. Spark utilise le connecteur Hadoop S3A. Iceberg utilise `S3FileIO`
(côté pyiceberg et côté runtime Spark). Les clients partagent l'endpoint, les
identifiants, la région et le mode `path-style` configurés dans `.env`.

## Organisation des objets

```text
s3://iceberg-warehouse/
  analytics/
    sessions/     # fichiers Parquet + métadonnées gérés par Iceberg
    messages/
    parts/
    tools/
  spark/          # agrégats écrits par le job Spark
```

Le warehouse Iceberg contient les fichiers et métadonnées gérés par Iceberg ;
il ne faut jamais le modifier manuellement. Le bucket
`opencode-analytics/parquet` des anciennes versions n'existe plus dans le
flux.

## Vérification avec AWS CLI

Le profil Docker `tools` fournit AWS CLI. Exemple avec RustFS :

```sh
docker-compose --profile tools run --rm aws-cli \
  --endpoint-url http://host.docker.internal:9000 \
  s3 ls s3://iceberg-warehouse/
```

Depuis l'hôte, `aws` peut aussi être utilisé avec :

```sh
aws --endpoint-url http://localhost:9000 s3 ls s3://iceberg-warehouse/
```

## Sécurité

Utiliser des secrets distincts par environnement, limiter les endpoints au
réseau nécessaire, ne pas activer d'accès public et ne pas envoyer les
identifiants dans Git. Les tables Iceberg contiennent potentiellement du
contenu utilisateur et des sorties de commandes.
