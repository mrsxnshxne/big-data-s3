# RustFS et S3

## Qu'est-ce que S3 ?

Amazon S3 est une interface de stockage objet : les données sont stockées sous
forme d'objets identifiés par un bucket et une clé, par exemple
`s3://opencode-analytics/parquet/sessions.parquet`. S3 n'est pas un système de
fichiers POSIX : les préfixes servent à organiser les clés, mais ne sont pas
des répertoires classiques.

Le stockage objet est adapté aux data lakes car il est durable, accessible par
HTTP et découplé des moteurs de calcul. Le format Parquet ajoute une
organisation en colonnes efficace pour les lectures analytiques.

## RustFS dans ce projet

RustFS est l'implémentation locale compatible avec l'API S3. Le service Docker
stocke ses données dans le volume `rustfs-data` et expose :

- API S3 : `http://localhost:9000`
- Console : `http://localhost:9001`

L'application utilise `boto3`. Spark utilise le connecteur Hadoop S3A. Iceberg
utilise `S3FileIO`. Les trois clients partagent l'endpoint, les identifiants,
la région et le mode `path-style` configurés dans `.env`.

## Organisation des objets

```text
s3://opencode-analytics/parquet/
  sessions.parquet
  messages.parquet
  parts.parquet
  tools.parquet

s3://iceberg-warehouse/
  analytics/
    sessions/
    messages/
    parts/
    tools/
```

Le premier bucket contient les fichiers d'échange. Le warehouse Iceberg
contient les fichiers et métadonnées gérés par Iceberg ; il ne faut pas le
modifier manuellement.

## Vérification avec AWS CLI

Le profil Docker `tools` fournit AWS CLI. Exemple avec RustFS :

```sh
docker-compose --profile tools run --rm aws-cli \
  --endpoint-url http://host.docker.internal:9000 \
  s3 ls s3://opencode-analytics/parquet/
```

Depuis l'hôte, `aws` peut aussi être utilisé avec :

```sh
aws --endpoint-url http://localhost:9000 s3 ls s3://opencode-analytics/parquet/
```

## Sécurité

Utiliser des secrets distincts par environnement, limiter les endpoints au
réseau nécessaire, ne pas activer d'accès public et ne pas envoyer les
identifiants dans Git. Les fichiers Parquet contiennent potentiellement du
contenu utilisateur et des sorties de commandes.
